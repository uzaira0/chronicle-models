# Current State Inventory

Status: accepted pre-refactor baseline. Dispositions in this inventory were implemented by the tranches recorded in [08-rollout-sequence.md](08-rollout-sequence.md); references to manual duplication describe the starting state, not the current architecture.

This inventory records the concrete source evidence that justifies the shared-contract refactor. It is not a code-change plan by itself; it defines where duplication exists and where each concept should move or remain.

| Android sensor types | `AndroidSensorType` and `SensorCollectionModules` | Android collection modules; web sensor list/order; backend Android sensor upload ingestion | Medium: adding a sensor can miss web UI or backend validation. | `chronicle-models` exports mapping and active status; backend verifies ingestion support; web consumes generated mapping for configuration. |
| iOS SensorKit sensor types | `SensorType` plus iOS `Sensor.swift` copy | iOS SensorKit adapters; shared model DTOs; Screen Time payload logic | High: Swift enum can drift from shared model and Apple framework strings. | `chronicle-models` owns stable value names; generated Swift exposes contract values; native adapter maps generated values to `SRSensor`. |
| API paths and route builders | `chronicle-api/chronicle.yaml` should own; iOS `ApiUtils.swift` duplicates | iOS route builders; web generated OpenAPI client/types; backend controller endpoints | High: path changes can break iOS silently. | Keep OpenAPI as owner; generate TypeScript API types and Swift route builders from OpenAPI paths. |

| DB tables and RLS policies | Backend Flyway migrations | Backend services and export jobs; indirectly all clients via ingestion/export behavior | High: active module can lack table, idempotency, scoping, export eligibility, or RLS coverage. | Backend owns schema; contract tests map active modules to handler/table/export/RLS obligations. |

## Boundary Observations

Android is closest to the intended architecture because it already consumes `chronicle-models` and `chronicle-api` through Gradle composite builds. The main Android cleanup is not to invent a new shared model path, but to separate Android-only storage/runtime concerns from pure collection contract consumption after the contract artifact is stable.

iOS has the largest duplication surface: API routes, DTOs, SensorKit values, date encoding behavior, and payload envelopes are manually maintained. The iOS refactor should prioritize generated Swift contracts and route builders while leaving Apple framework adapters native.

Web already has OpenAPI generation but still maintains domain constants manually. The web refactor should replace domain value sets with generated domain contracts while preserving web-owned presentation metadata such as labels, descriptions, grouping, and UI ordering.

Backend and DB should not export schema to clients. They need explicit coverage matrices proving that active modules have ingestion handlers, storage, scoping, idempotency, RLS, and export behavior.
